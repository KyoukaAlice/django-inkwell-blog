Overview

项目概览

一个功能完整的单体 Django 应用：服务端渲染为主 + 少量 AJAX 局部刷新， 不依赖任何前端框架与构建工具，克隆下来装完依赖就能跑。

🧩

完整的业务闭环

从注册登录、写作发布、分类标签，到阅读互动、消息通知、个人中心， 博客该有的环节都跑通了，没有半成品页面。

⚙️

零构建的前端

原生 HTML / CSS / JavaScript，一份设计系统 CSS 管理全站样式， 没有 npm、没有打包步骤，改完刷新即可看到效果。

🗄️

MySQL / SQLite 双支持

默认走 MySQL，设一个环境变量即可切到 SQLite， 迁移与代码完全兼容，方便在没有数据库的机器上演示。

# blog/models.py
class Comment(models.Model):
    post   = models.ForeignKey(Post, related_name='comments')
    author = models.ForeignKey(User)
    parent = models.ForeignKey('self', null=True,   # 直接回复谁
                              related_name='replies')
    root   = models.ForeignKey('self', null=True,   # 属于哪个楼层
                              related_name='thread_comments')
    depth  = models.PositiveSmallIntegerField(default=0)
    is_deleted = models.BooleanField(default=False)   # 软删除

    def save(self, *args, **kwargs):
        # root / depth 由模型自己维护，视图层不用管
        if self.parent_id:
            self.root_id = self.parent.root_id or self.parent_id
            self.depth = min(self.parent.depth + 1, self.MAX_DEPTH)
        super().save(*args, **kwargs)
# 楼层树长这样（一次查询取回，零递归；再深也压平到 depth=2）
楼层 A ── root=None, depth=0
  ├─ 回复 1 ── root=A, depth=1
  ├─ 回复 2 ── root=A, depth=1
  │    └─ 楼中楼 ── root=A, depth=2
  └─ 回复 3 ── root=A, depth=1

两个关键取舍

  • 为什么要 root：只用一个 parent 自关联，渲染时得递归查库， 层数一深就 N+1；有了 root 就能一次 SELECT 取回整棵树，在内存里组装。
  • 为什么要软删除：物理删除会让楼层号凭空消失（用户看到 #5 楼没了 会以为出 bug），楼中楼回复也会变成孤儿。软删除只清空内容、保留占位。
Workflow

一次评论请求的处理流程

从用户点下「发送」到评论区更新，服务端与前端各自做了什么。

①

校验

按顺序校验：内容非空 → 回复目标必须属于同一篇文章 → 15 秒频率限制。 顺序是刻意的，否则非法的 parent_id 会被误报成「发言太快」。

②

落库

保存时由 Comment.save() 自动推导 root 与 depth； 同时按「回复优先通知被回复人，否则通知楼主」生成站内通知，且不给自己发。

③

组装楼层树

一次带 select_related + Prefetch 的查询取回全部评论、 作者资料与点赞，再在内存里按 root 分组、排序、分页。

④

局部渲染

整个评论区是一个独立的局部模板，服务端渲染成 HTML 片段后回给前端， 前端直接替换 #comments 容器内容 —— 全程不刷新页面。

⑤

事件委托

点赞 / 回复 / 删除的监听全部绑在容器上。因为容器内容会被替换， 用 querySelectorAll 绑定的话新出现的按钮会点不动。

⑥

无 JS 兜底

表单本身是标准 form method="post"， JavaScript 加载失败时依然能正常提交，只是会整页刷新。

查询次数上界（防 N+1）

用 assertNumQueries 把首页和详情页的查询次数钉死： 首页 29 → 13 次，详情页 17 次。 以后谁在模板里写出没预取的访问，测试立刻失败。

🔒

安全细节

  • CSRF：表单 + AJAX 请求头双重携带
  • XSS：Markdown 渲染后过一遍白名单
  • 开放重定向：登录 next 参数做站内校验
  • 上传：扩展名白名单 + 5MB 上限 + 真伪校验
  • 密码：Django 强度校验 + 加密摘要存储
🔗

预览站的链接完整性

静态快照生成时会自动把站内绝对路径改写成相对路径， 并自检「每个相对链接是否都能找到文件」。 当前 1600+ 个链接，0 死链。

Get Started

本地运行

Windows 下双击脚本即可完成环境准备、建表与数据初始化。

关于本页　这是项目展示页，配合 静态快照用于浏览界面。 完整的博客功能需要运行 Python 服务（Django 后端 + 数据库）， 而 GitHub Pages 只能托管静态文件，所以登录、发文、点赞、发评论这些操作在这里不会生效。 想体验完整功能请按下面步骤在本地启动。

① 一键脚本（Windows）

git clone https://github.com/KyoukaAlice/django-inkwell-blog.git
cd django-inkwell-blog

:: 建虚拟环境 + 装依赖 + 建表 + 生成表情 + 演示数据
setup_env.bat sqlite demo

:: 启动（sqlite 表示不用装 MySQL）
start.bat sqlite

浏览器打开 http://127.0.0.1:8000/

② 手动命令（macOS / Linux）

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python manage.py migrate
python manage.py generate_emoticons   # 生成表情 SVG
python manage.py seed_demo            # 演示数据（可选）
python manage.py runserver
